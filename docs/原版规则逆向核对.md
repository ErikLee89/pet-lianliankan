# 连连看 v4.1 原版规则逆向核对

分析对象：`D:\Program Files (x86)\llkwqb\zzllk.exe`，1,867,776 字节。

SHA-256：`718bc930b460ff7653bbe029d360d725fd73ed727ff4f80369d7198e9cab1454`。

本报告来自原版 x86 机器码、跳转表、中文字符串和 WAVE 资源的静态交叉核对。没有修改原版或复刻程序，也没有进行原版运行时断点验证。地址均为 ImageBase=0x400000 下的虚拟地址。跳转表按数据解析，不作为指令执行流程阅读。

## 1. 状态字段

下列偏移相对于游戏对象 this；在主要函数中 this 保存于 ESI，部分函数使用 EBX/EDI。

| 偏移 | 含义 | 主要证据 |
|---|---|---|
| +0xAB4 | 难度，1–4 | 四个开局函数及事件分派 |
| +0xAB8 | 内部关卡，1–11 | 0x404E21、0x405010；界面显示时减 1（0x408766） |
| +0xABC | 生命/可洗牌次数 | 洗牌函数 0x4064F0 扣 1；界面文字“生命” |
| +0xAC0 | 提示次数 | 提示函数 0x406020 扣 1 |
| +0xAC4 | 积分 | 消除、过关、随机奖励和成绩保存共同引用 |
| +0xD8 | 时间槽整数 T | 开关卡设为 300，定时器递减，绘制时间条 |
| +0x8C | 当前事件编号；-1 表示没有事件 | 事件分派与 3 秒清除定时器 |
| +0xF4 | 音效开关 | 大多数动作声音之前检查；随机奖励函数没有相同检查 |

## 2. 积分、时间与资源

### 消除一对

`0x404D35–0x404D5C`：

```text
score += 10
T += 5
if T > 300:
    T = 302
```

302 是代码中的实际常量，不是笔误。每对不是复刻中的 2 分，时间也不是固定增加 2 秒。

### 过关

普通过关 `0x404E61–0x404E97`，全部通关 `0x405094–0x4050CA` 使用同一奖励公式：

```text
bonus = T + 20 * remaining_lives + 10 * remaining_hints
score += bonus
```

普通过关随后在 `0x405010–0x405039` 执行：下一关、生命 +1、提示 +1，然后重新布置棋盘和把 T 设为 300。奖励先计算，再增加下一关资源。

### 失败

- 时间耗尽：`0x40577F–0x405796` 给积分 **+100**，原版字符串 `0x4467CC` 明确写着“时间到！加时间能量100分”。
- 死局且没有生命：`0x4052A2–0x4052ED` 结束游戏，此分支没有上述 +100。
- 死局但还有生命：调用 `0x4064F0`，扣一次生命并洗牌。
- 手动提示：有提示次数且找到可消除的一对，才扣提示 1（`0x406020–0x406078`）。
- 手动/自动洗牌共同经过 `0x4064F0`：有生命才扣 1 并重排。

### 各难度开局

| 难度编号 | 初始生命 | 初始提示 | Timer 2 间隔 | T=300 的名义消耗时间 |
|---|---:|---:|---:|---:|
| 1 | 2 | 4 | 600 ms | 180 s |
| 2 | 3 | 6 | 700 ms | 210 s |
| 3 | 4 | 8 | 800 ms | 240 s |
| 4 | 5 | 10 | 830 ms | 249 s |

证据：`0x4049D0`、`0x404A40`、`0x404AB0`、`0x408250`。初始积分均为 0。名义时间只做单位换算：Windows 消息调度、暂停及到零后的下一次回调均会影响实测结束时间。不要把这张表理解为已运行测定的精确倒计时。

Timer 2 在 `0x4056B3` 开始处理，检查游戏/暂停等状态后，每次 T 减 1。时间为 0 时，在下一次处理进入失败分支。当前事件显示使用独立 Timer 3，3000 ms 后置回 -1（`0x405810–0x405824`）。

## 3. 奖励与惩罚

### 触发条件及调用顺序

成功消除先加分和时间、移动牌、清空选中状态，然后检查是否还有可消除对。只有仍有可消除对的路径，才在 `0x405321` 调用事件函数 `0x4080C0`；过关和死局处理路径直接返回。

事件函数先检查：

```text
T % 12 == 11
current_event < 0
```

满足后取 `rand() % 7`。`rand()` 位于 `0x41E7F7`，是返回 0–32767 的 CRT 伪随机数函数。7 个结果近似均匀，取模有极小偏差。**不存在每次消除固定 15% 触发或统一“奖励70%、惩罚30%”的逻辑。** 因为 T 在计时、消除、事件时都会改变，实际出现频率依赖操作节奏。

事件成功执行后显示 3 秒，在此期间不再产生新事件。若惩罚的附加条件不满足，恢复 current_event=-1，不重抽，也不显示此次事件。

### 难度 1–3

跳转表 `0x408234`；事件函数 `0x4080D3–0x408230`。

| rand()%7 | 效果 | 附加条件 | WAVE 编号 | 分支地址 |
|---:|---|---|---:|---|
| 0 | 提示 +2 | 无 | 145 | 0x40811B |
| 1 | 分数 +2500 | 无 | 145 | 0x40814B |
| 2 | 提示 -1 | 提示≥1，且另一次 rand()%2==0 | 144 | 0x408157 |
| 3 | 提示 +1 | 无 | 143 | 0x408183 |
| 4 | T +14 | 无 | 143 | 0x4081AF |
| 5 | 分数 +1000 | 无 | 143 | 0x4081B8 |
| 6 | T -14 | T≥70，且另一次 rand()%2==0 | 144 | 0x4081C4 |

在这一事件函数中，没有扣分、扣生命或奖励生命的分支，也没有对奖励后的 T 做 300 上限裁剪。消除时的 302 裁剪是另一处独立逻辑。

原版文案称时间增减为“七秒”，但机器码增减值是 14。根据本版本开局定时器配置，14 单位名义上分别对应 8.4、9.8、11.2 秒；应保留代码与文案之间的差异。

### 难度 4

`0x4080C3` 检查难度等于 4 时改调 `0x4088D0`；跳转表 `0x408A2C`。触发门槛相同，但全部分支是奖励。

| rand()%7 | 效果 | 显示事件编号 | WAVE 编号 | 分支地址 |
|---:|---|---:|---:|---|
| 0 | 提示 +2 | 0 | 145 | 0x40891B |
| 1 | 提示 +4 | 10 | 146 | 0x408927 |
| 2 | 生命/洗牌 +1 | 7 | 143 | 0x408945 |
| 3 | 提示 +1 | 3 | 143 | 0x40895E |
| 4 | T +14 | 4 | 143 | 0x408966 |
| 5 | 生命/洗牌 +2 | 8 | 145 | 0x408993 |
| 6 | 生命/洗牌 +4 | 9 | 146 | 0x4089D2 |

本难度 T+14 名义上对应 11.62 秒，文案仍沿用“七秒”。

## 4. 动作与音效

直接从调用 PlaySoundA（导入地址 `0x43B51C`）前的资源 ID 参数追踪。资源 ID 为十进制，可对应 `assets/sfx/wav_<编号>.wav`。

| 动作/事件 | ID | 关键地址 |
|---|---:|---|
| 点选牌进入选择状态 | 138 | 0x405478 |
| 成功消除一对 | 139 | 0x404D21 |
| 两张相同但无法连通 | 140 | 0x405397 |
| 两张不同的牌 / 取消选择 | 147 | 0x4053B3 / 0x408493 |
| 普通奖励：提示+1、T+14、普通难度分数+1000；第四档生命+1 | 143 | 0x4081A8 / 0x40898C |
| 惩罚：提示-1 或 T-14 | 144 | 0x408206 |
| 较大奖励：提示+2、普通难度分数+2500；第四档生命+2 | 145 | 0x408141 / 0x4089CB |
| 第四档奖励提示+4、生命+4 | 146 | 0x408A0A |
| 全部通关 | 148 | 0x405083 |
| 普通过关 | 149 | 0x404E51 |
| 有效提示 | 150 | 0x406058 |
| 时间耗尽 / 无生命可解死局 | 151 | 0x405774 / 0x4052CB |
| 洗牌 | 152 | 0x406518 |

在已识别的游戏声音调用中，未发现 137、141、142、153、154 的播放路径。不能因资源存在就分配为某个动作；尤其当前复刻将 153 指作“开局音”，原版此处没有找到相应证据，也未找到低时间滴答音的调用。

消除音使用 flags=0x40084，其余列出的动作使用 0x40085；相差的 bit 0 对应同步/异步播放。原版关闭音效时，消除路径改为 Sleep(300)，这是操作节奏相关的另一个细节（0x404D2A）。

事件函数直接播放声音，未检查 +0xF4；普通动作一般先检查。这里记录机器码行为，尚未运行确认关闭音效后奖励音是否仍可听到。

### 当前复刻音频文件的字节核对

`match.wav`、`cancel.wav`、`hint.wav`、`shuffle.wav`、`gameover.wav`、`win.wav` 和主要奖励文件能与相应原版 WAVE 资源逐字节匹配。

`select.wav` 与原版 138、`error.wav` 与原版 140、`winall.wav` 与原版 148 **不是字节完全一致的文件**，但项目同时保留了对应 `wav_138.wav`、`wav_140.wav`、`wav_148.wav` 原始文件。字节不一致本身不能证明听感差异大小，后续若要求原样还原，应使用已核对的原始资源。

## 5. 与当前复刻的主要差异

| 项目 | 当前复刻 | 原版静态证据 |
|---|---|---|
| 消除得分 | +2 | +10 |
| 消除补时 | +2秒 | +5 时间槽单位；超过300设302 |
| 开局生命/提示 | 自定义难度配置、提示3 | 生命2/3/4/5，提示4/6/8/10 |
| 普通过关资源 | 生命+1 | 生命+1且提示+1 |
| 过关积分 | 复刻自定义 | T+20×生命+10×提示 |
| 时间耗尽积分 | 没有+100 | +100 |
| 随机事件门槛 | 每对15% | T%12==11且没有当前事件 |
| 抽奖结构 | 奖惩70:30，按资源加权 | 七分支；惩罚分支还需额外检查 |
| 第四档 | 共用奖惩规则 | 独立七分支，全奖励 |
| 随机积分 | ±10 | +1000/+2500；该函数无扣分 |
| 奖励音 | 按奖励类型分配 | 按上表分支分配 |

后续实施应以时间槽 T 为基础，保持判断顺序，再换算 UI 显示；直接替换几个概率或秒数不能复现该程序。尚未开展原版调试器断点验证，当前结论不包含操作耗时或声音听感一致性承诺。
